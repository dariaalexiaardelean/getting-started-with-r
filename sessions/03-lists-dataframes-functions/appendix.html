memclinic <- read.csv("data/memclinic.csv")
memclinic$group <- factor(memclinic$group, levels = c("HC", "MCI", "AD"))

Lists are not vectorised

xlis <- list(1, 2, 3)
xlis^2
Error in `xlis^2`:
! non-numeric argument to binary operator

Arithmetic works elementwise on a vector; a list is a generic container, so there is nothing to apply the operation to. The fix is to map a function over it:

purrr::map(xlis, function(x) x^2)
lapply(xlis, function(x) x^2)
[[1]]
[1] 1

[[2]]
[1] 4

[[3]]
[1] 9

The apply family

vars <- c("age", "moca", "hippo_vol_mm3")

sapply(memclinic[, vars], mean)     # simplifies to a vector
          age          moca hippo_vol_mm3 
     69.87222      24.25000    3484.96111 
sapply(memclinic[, vars], range)    # ... or a matrix
     age moca hippo_vol_mm3
[1,]  50   16          2634
[2,]  91   30          4571
str(lapply(memclinic[, vars], mean))   # lapply always returns a list
List of 3
 $ age          : num 69.9
 $ moca         : num 24.2
 $ hippo_vol_mm3: num 3485

sapply() guesses at the output shape, which is convenient interactively and risky in a script. vapply() makes you state it, and then checks:

vapply(memclinic[, vars], mean, numeric(1))
          age          moca hippo_vol_mm3 
     69.87222      24.25000    3484.96111 
names(Filter(is.numeric, memclinic))
[1] "age"            "educ_years"     "moca"           "hippo_vol_mm3" 
[5] "stroop_cost_ms" "rt_mean"        "csf_ptau"      
pieces <- lapply(levels(memclinic$group), function(g) {
  d <- memclinic[memclinic$group == g, ]
  data.frame(group = g, n = nrow(d), mean_moca = round(mean(d$moca), 1))
})
do.call(rbind, pieces)

do.call(rbind, ...) stacks a list of data frames into one, and is the idiom you will see in simulation code.

Preallocation, and why it matters

groups <- levels(memclinic$group)

out <- numeric(length(groups))          # room reserved up front
for (i in seq_along(groups)) {
  out[i] <- mean(memclinic$moca[memclinic$group == groups[i]])
}
names(out) <- groups
round(out, 1)
  HC  MCI   AD 
28.4 25.2 19.2

Growing out with c(out, value) instead would make R copy the whole vector on every pass. For three groups it makes no difference; for a simulation with 10 000 iterations it is the difference between seconds and minutes.

Anonymous functions and functions in lists

sapply(memclinic[, c("age", "moca")], function(x) max(x) - min(x))
 age moca 
  41   14 
# R 4.1 shorthand
sapply(memclinic[, c("age", "moca")], \(x) max(x) - min(x))
 age moca 
  41   14 
funs <- list(mean = mean, median = median, sd = sd)
sapply(funs, function(f) round(f(memclinic$moca), 2))
  mean median     sd 
 24.25  25.00   4.16

Functions are objects like anything else, so they can live in a list and be passed around.

Composing functions, and pipes

x <- c(4, 9, 16)

step1 <- log(x); exp(step1)       # step by step
[1]  4  9 16
exp(log(x))                       # nested, read inside out
[1]  4  9 16
x |> log() |> exp()               # native pipe, read left to right
[1]  4  9 16

The lecture teaches %>% from magrittr, which is what the tidyverse uses and what appears in WinterBreakExercises.R:

library(magrittr)
x %>% log %>% exp

For straightforward use the two behave the same. |> is built into R and needs no package.

Lexical scoping

z <- 10
f <- function() { z <- 99; z }

f()    # the local z
[1] 99
z      # the global one, untouched
[1] 10

Name masking: a name defined inside a function hides one outside it. Dynamic lookup: R looks inside the function first, then outward. In the lecture’s phrasing — what happens in the function stays in the function, unless you super-assign with <<-, which you should almost never do.

g <- function(a, b) a * 2
g(5)      # no error, even though b was never supplied
[1] 10

That is lazy evaluation: arguments are only evaluated if they are actually used. b was never touched, so its absence never came up.

Nested lists

study <- list(
  site_PD = list(n = 120, lead = "Padova"),
  site_VR = list(n = 60,  lead = "Verona")
)

study$site_PD$n
[1] 120
study[["site_VR"]][["lead"]]
[1] "Verona"
sapply(study, function(s) s$n)
site_PD site_VR 
    120      60 
sum(sapply(study, function(s) s$n))
[1] 180

A fitted model is exactly this shape, several levels deep, which is why str() on one produces so much output — and why names() is the friendlier way in.

fit <- lm(stroop_cost_ms ~ hippo_vol_mm3, data = memclinic)
names(summary(fit))
 [1] "call"          "terms"         "residuals"     "coefficients" 
 [5] "aliased"       "sigma"         "df"            "r.squared"    
 [9] "adj.r.squared" "fstatistic"    "cov.unscaled" 
summary(fit)$r.squared
[1] 0.5340545
summary(fit)$coefficients["hippo_vol_mm3", "Pr(>|t|)"]
[1] 2.466457e-31

Pulling a p value out by name like that is how you avoid retyping numbers into a report — and how you avoid the typo that follows.
