Lists

A list is a generic vector: a collection of components that can be objects of different types, and of different lengths.

(lis1 <- list(1:5, c("a", "b"), c(TRUE, FALSE, TRUE), 2.3))
[[1]]
[1] 1 2 3 4 5

[[2]]
[1] "a" "b"

[[3]]
[1]  TRUE FALSE  TRUE

[[4]]
[1] 2.3
str(lis1)
List of 4
 $ : int [1:5] 1 2 3 4 5
 $ : chr [1:2] "a" "b"
 $ : logi [1:3] TRUE FALSE TRUE
 $ : num 2.3
typeof(lis1)
[1] "list"
is.list(lis1)
[1] TRUE

Components are usually named:

patient <- list(id      = "P042",
                age     = 71,
                group   = "MCI",
                scores  = c(moca = 24, stroop = 118))
str(patient)
List of 4
 $ id    : chr "P042"
 $ age   : num 71
 $ group : chr "MCI"
 $ scores: Named num [1:2] 24 118
  ..- attr(*, "names")= chr [1:2] "moca" "stroop"

A list can contain a list, which makes it a recursive object — and is how every complicated thing in R is built.

WarningBeware the relation between c() and lists 
lis2 <- list(list(1, "a"), c(TRUE, FALSE))    # a list of 2
lis3 <- c(list(1, "a"), c(TRUE, FALSE))       # a list of 4

length(lis2); length(lis3)
[1] 2
[1] 4

list() nests. c() flattens one level. They look almost identical and do different things.

Subsetting a list — [, [[, $

This is the single most confusing thing about lists, and it is worth ten minutes now to save an hour later.

patient["age"]      # SINGLE bracket: a LIST containing age
$age
[1] 71
patient[["age"]]    # DOUBLE bracket: the value itself
[1] 71
patient$age         # the same as [[ ]], for a named component
[1] 71
class(patient["age"])
[1] "list"
class(patient[["age"]])
[1] "numeric"

[ keeps the container, [[ opens it. The usual image: a list is a train of carriages, [ gives you a shorter train, [[ gives you what is inside one carriage.

patient[c("id", "group")]    # several components: still a list
$id
[1] "P042"

$group
[1] "MCI"
patient[-1]                  # drop the first component
$age
[1] 71

$group
[1] "MCI"

$scores
  moca stroop 
    24    118 
patient[["scores"]]["moca"]  # into a component, then inside it
moca 
  24 
patient$scores["moca"]       # the same
moca 
  24

unlist() flattens the whole thing to a vector — note the coercion:

unlist(patient)
           id           age         group   scores.moca scores.stroop 
       "P042"          "71"         "MCI"          "24"         "118"

Data frames are lists

Matrices are built on top of vectors with a dim attribute. Factors are built on top of vectors with class and levels. Dataframes are built on top of lists.

A data frame is a named list of vectors, all of the same length, with three attributes: names, class, and row.names.

age   <- c(72, 68, 81, 74, 69)
sex   <- c("M", "F", "F", "M", "F")
group <- c("HC", "MCI", "AD", "HC", "MCI")

(df1 <- data.frame(age = age, sex = sex, group = group))
str(df1)
'data.frame':   5 obs. of  3 variables:
 $ age  : num  72 68 81 74 69
 $ sex  : chr  "M" "F" "F" "M" ...
 $ group: chr  "HC" "MCI" "AD" "HC" ...
attributes(df1)
$names
[1] "age"   "sex"   "group"

$class
[1] "data.frame"

$row.names
[1] 1 2 3 4 5
typeof(df1)      # a list!
[1] "list"
class(df1)       # ... labelled data.frame
[1] "data.frame"

Which means all the list subsetting you just learned applies:

length(df1)      # the number of COLUMNS
[1] 3
df1[1]           # a data frame with one column
df1[[1]]         # the column itself, as a vector
[1] 72 68 81 74 69
df1$age          # the same
[1] 72 68 81 74 69

But a data frame also has the properties of a matrix, so [row, column] works too:

dim(df1); nrow(df1); ncol(df1)
[1] 5 3
[1] 5
[1] 3
colnames(df1)
[1] "age"   "sex"   "group"
df1[2, ]          # second row
df1[, "age"]      # the age column
[1] 72 68 81 74 69
df1[2, "age"]     # one cell
[1] 68

That double nature — list and matrix at once — is what makes a data frame the right object for a dataset.

WarningstringsAsFactors 
is.factor(df1$sex)
[1] FALSE

Since R 4.0.0 text columns stay as text. Older code and older textbooks assume the opposite. Convert explicitly when you need a factor.

summary() behaves differently on factors

summary(df1)
      age           sex               group          
 Min.   :68.0   Length:5           Length:5          
 1st Qu.:69.0   Class :character   Class :character  
 Median :72.0   Mode  :character   Mode  :character  
 Mean   :72.8                                        
 3rd Qu.:74.0                                        
 Max.   :81.0

sex and group report Length / Class / Mode, which tells you nothing. Turn them into factors and the same call counts them:

df1_F <- as.data.frame(unclass(df1), stringsAsFactors = TRUE)
summary(df1_F)
      age       sex   group  
 Min.   :68.0   F:3   AD :1  
 1st Qu.:69.0   M:2   HC :2

 Max.   :81.0

df1$moca <- c(29, 24, 17, 28, 25)
df1$age_z <- with(df1, scale(age))    # with() saves repeating df1$
str(df1)

 $ age  : num  72 68 81 74 69

Tibbles

A tibble is a modern data frame from the tidyverse, which drops some of the older idiosyncrasies and prints more helpfully — it borrows the type information from str() and puts it in the printout.

(tib0 <- tibble::tibble(x    = 1:3,
                        y    = 1,
                        z    = x^2 + y,
                        name = letters[1:3]))
class(tib0)
[1] "tbl_df"     "tbl"        "data.frame"
tibble::is_tibble(tib0)
[1] TRUE

Note y = 1 was recycled, and z could be defined using x and y in the same call — neither works in data.frame(). A tibble is still a data frame: [, [[ and $ all behave as you expect.

Control flow

Choices

score <- 24
if (score < 26) {
  print("below the screening cut-off")
} else {
  print("within normal limits")
}
[1] "below the screening cut-off"

if() takes one condition. For a whole vector, use the vectorised ifelse():

x <- 1:8
ifelse(x %% 2 == 0, "even", "odd")
[1] "odd"  "even" "odd"  "even" "odd"  "even" "odd"  "even"
moca <- c(29, 24, 18, 27)
dplyr::case_when(
  moca >= 26 ~ "normal",
  moca >= 20 ~ "mild",
  TRUE       ~ "moderate-severe"
)
[1] "normal"          "mild"            "moderate-severe" "normal"

case_when() replaces nested ifelse(). The conditions are evaluated in the order you write them, and the first match wins, so >= 26 must come before >= 20. The final TRUE is the catch-all.

Loops

for (i in 1:4) print(i)
[1] 1
[1] 2
[1] 3
[1] 4
for (g in c("HC", "MCI", "AD")) {
  cat(g, "\n")
}
HC 
MCI 
AD

next skips to the next iteration, break leaves the loop:

for (i in 1:10) {
  if (i < 2) next
  if (i > 6) break
  cat(i, "")
}
2 3 4 5 6 
x <- 0
while (x < 4) { x <- x + 1 }
x
[1] 4
x <- 0
repeat { x <- x + 1; if (x == 4) break }
x
[1] 4

while tests the condition before each pass, repeat runs until you break out. There is no do-while statement in R.

WarningPitfalls in loops
  1. Preallocate — growing a vector each pass makes R copy it each time.
  2. Loops can strip attributes from vectors.
  3. Vectorise rather than nesting loops.
  4. 1:length(x) fails on an empty vector. Use seq_along(x):
x <- numeric(0)
1:length(x)      # counts DOWN from 1 to 0 -- two iterations on nothing
[1] 1 0
seq_along(x)     # empty, as it should be
integer(0)

Functions

In data analysis, functions are how you call statistical methods — and they typically return a list holding both results and details.

ttestex <- t.test(1:100, mu = 70)
class(ttestex)
[1] "htest"
names(ttestex)
 [1] "statistic"   "parameter"   "p.value"     "conf.int"    "estimate"   
 [6] "null.value"  "stderr"      "alternative" "method"      "data.name"  
ttestex$p.value
[1] 1.159984e-09
ttestex$conf.int
[1] 44.74349 56.25651
attr(,"conf.level")
[1] 0.95

Everything printed in a test result is a component you can pull out by name — which is how you put a number into a report without retyping it.

The same is true of a fitted model:

memclinic <- read.csv("data/memclinic.csv")
fit <- lm(stroop_cost_ms ~ hippo_vol_mm3, data = memclinic)

class(fit)
[1] "lm"
names(fit)[1:6]
[1] "coefficients"  "residuals"     "effects"       "rank"         
[5] "fitted.values" "assign"       
fit$coefficients
  (Intercept) hippo_vol_mm3 
  339.5534002    -0.0641034

class() is "lm", and that label is the whole reason summary(fit) prints a regression table rather than dumping a list. What that table means is the subject of the Regression 1 lecture.

Writing your own

hypo <- function(a, b) {
  c = sqrt(a^2 + b^2)
  return(c)
}

hypo(3, 4)
[1] 5
hypo(a = 3, b = 4)
[1] 5

Notice the assignment discipline: <- binds the function to the name, = names arguments at the call site.

A function has three parts:

formals(hypo)      # its arguments
$a


$b
body(hypo)         # what it does
{
    c = sqrt(a^2 + b^2)
    return(c)
}

Arguments can have defaults, and the last expression is returned even without return():

z_score <- function(x, na.rm = TRUE) {
  (x - mean(x, na.rm = na.rm)) / sd(x, na.rm = na.rm)
}

round(z_score(c(24, 26, 28, 30, 22)), 2)
[1] -0.63  0.00  0.63  1.26 -1.26
WarningMistakes can be silent

Be careful with arguments and their position.

sum(2, 3, 10)
[1] 15
mean(2, 3, 10)
[1] 2
args(mean)
function (x, ...) 
NULL

sum() adds everything it is given. mean() takes one vector as its first argument, so mean(2, 3, 10) returns the mean of 2 — and silently ignores the rest. What you meant was mean(c(2, 3, 10)).

f <- function() { hidden <- 99; hidden }
f()
[1] 99
exists("hidden")
[1] FALSE

What happens in the function stays in the function.

Exercise 4 — write a function

Write a function that takes a vector of scores and returns how many fall below a cut-off, with the cut-off as an argument that defaults to 26.

n_below <- function(x, cutoff = ___) {
  sum(x < cutoff, na.rm = TRUE)
}

n_below(memclinic$moca)
n_below(memclinic$moca, cutoff = ___)

formals(n_below)

# Now break it on purpose: what does this give, and why?
mean(24, 26, 28)
mean(c(24, 26, 28))

What to take away

  • [ keeps the container, [[ and $ open it.
  • A data frame is a list of equal-length columns, wearing a class label. length() counts columns; use nrow() for rows.
  • if takes one condition; ifelse() and case_when() take a whole vector.
  • case_when() stops at the first match, so order the conditions from specific to general.
  • A statistical function returns a list — everything in a printed result can be pulled out by name.
  • Check the argument order of a function before you trust its answer.
