4 · Working with data, and drawing it

Statistics for brain and cognitive sciences (CN2)

Note

Optional extra practice, and unlike practicals 1 to 3 this one runs alongside no lecture at all. It covers the handling and plotting that Prof. Noventa’s analysis scripts assume you already know, and that the Introduction to R lectures do not cover. Nothing here is assessed.

What you will be able to do

By the end of this practical you should be able to:

  • pull out the rows and columns you want, and sort a table;
  • create a new variable by recoding an existing one;
  • set the order of a factor’s levels, and say why that changes a model;
  • summarise a variable within each diagnostic group;
  • draw a histogram, a boxplot and a scatterplot, with axes a reader can understand;
  • turn a wide table into a long one, which is the shape repeated-measures analyses need.

Rows and columns

Inside [ ], what comes before the comma chooses rows and what comes after it chooses columns.

memclinic[1:3, ]                                # first three people
memclinic[memclinic$group == "AD", ][1:3, ]     # the AD patients
head(memclinic[, c("id", "group", "moca")], 3)  # three columns
WarningMistakes can be silent

Asking for one column with a comma gives you a vector; asking for two gives you a data frame.

class(memclinic[memclinic$group == "AD", "moca"])
[1] "integer"
class(memclinic[memclinic$group == "AD", c("id", "moca")])
[1] "data.frame"

This catches people when a function suddenly complains that it was given a vector where it wanted a table.

subset() says the same thing more readably:

severe <- subset(memclinic, group == "AD" & moca < 20)
nrow(severe)
[1] 36

Note it takes bare column names, with no memclinic$. It is a convenience for interactive work; inside your own functions it can behave unexpectedly, so the [ ] form is the safer habit.

Sorting

order() returns the positions that would put a vector in order, and you feed those back in as row numbers.

smallest <- memclinic[order(memclinic$hippo_vol_mm3), ]
head(smallest[, c("id", "group", "hippo_vol_mm3")], 3)
largest <- memclinic[order(-memclinic$hippo_vol_mm3), ]
head(largest[, c("id", "group", "hippo_vol_mm3")], 3)

(sort() sorts a single vector; order() is what you need to reorder a whole table.)

Making new variables

ifelse() works through a vector and returns one of two values for each element.

memclinic$screen <- ifelse(memclinic$moca < 26, "below cut-off", "normal")
table(memclinic$screen)

below cut-off        normal 
           97            83

For more than two outcomes, nested ifelse() becomes unreadable. The professor’s tool for this is case_when():

memclinic$severity <- dplyr::case_when(
  memclinic$moca >= 26 ~ "normal",
  memclinic$moca >= 20 ~ "mild",
  TRUE                 ~ "moderate-severe"
)
table(memclinic$severity)

           mild moderate-severe          normal 
             61              36              83

Conditions are checked in the order you write them, and the first match wins — which is why >= 26 has to come before >= 20. The final TRUE is the catch-all.

Factors, and why their order matters

In practical 2 you saw that group arrives as text, and that making it a factor sorts the levels alphabetically:

levels(factor(memclinic$group))
[1] "AD"  "HC"  "MCI"

AD first. That is not how anyone would present these groups, and it is not harmless, because the first level becomes the baseline that everything else is compared against.

coef(lm(moca ~ factor(group), data = memclinic))
     (Intercept)  factor(group)HC factor(group)MCI 
        19.18333          9.20000          6.00000

The intercept, 19.18, is the AD mean. Now set the order deliberately:

memclinic$group <- factor(memclinic$group, levels = c("HC", "MCI", "AD"))
levels(memclinic$group)
[1] "HC"  "MCI" "AD" 
coef(lm(moca ~ group, data = memclinic))
(Intercept)    groupMCI     groupAD 
   28.38333    -3.20000    -9.20000

The intercept is now 28.38, the HC mean, and the other two numbers are the MCI and AD deficits relative to healthy controls — which is what a clinical reader expects. Same data, same model, every number different.

contrasts(memclinic$group)
    MCI AD
HC    0  0
MCI   1  0
AD    0  1

That matrix is what R actually put into the model. Practical 6 is about nothing else.

relevel() moves one level to the front without retyping them all:

levels(relevel(memclinic$group, ref = "AD"))
[1] "AD"  "HC"  "MCI"

Summarising by group

tapply(memclinic$moca, memclinic$group, mean)
      HC      MCI       AD 
28.38333 25.18333 19.18333

aggregate() does the same with a formula, and handles several variables at once:

aggregate(moca ~ group, data = memclinic, FUN = mean)
aggregate(cbind(hippo_vol_mm3, csf_ptau) ~ group, data = memclinic, FUN = mean)

with() saves repeating the data frame name:

with(memclinic, tapply(hippo_vol_mm3, group, median))
    HC    MCI     AD 
3855.0 3489.0 3111.5

The psych package gives a fuller description, including skewness:

psych::describe(memclinic[, c("moca", "hippo_vol_mm3", "csf_ptau")])
Warning

Select the columns you want first. psych::describe(memclinic) will happily report a mean for id and group, marking them with a * — a number that means nothing. This is why the course scripts write psych::describe(memclinic[, c("hippo_vol_mm3", "stroop_cost_ms")]) instead.

Look at skew for csf_ptau: strongly positive, so the distribution has a long right tail and its mean sits well above its median. The next section makes that visible.

Drawing the data

One variable: a histogram

hist(memclinic$csf_ptau,
     breaks = 20,
     main   = "CSF phosphorylated tau",
     xlab   = "p-tau (pg/mL)")

There is the skew from the table above.

One variable per group: a boxplot

boxplot(moca ~ group, data = memclinic,
        xlab = "Diagnosis",
        ylab = "MoCA score")

The groups come out in clinical order because we fixed the factor levels earlier. Had we not, this plot would read AD, HC, MCI.

Two variables: a scatterplot

plot(memclinic$hippo_vol_mm3, memclinic$stroop_cost_ms,
     pch  = 16,
     col  = "grey40",
     xlab = "Hippocampal volume (mm³)",
     ylab = "Stroop interference cost (ms)")

abline(lm(stroop_cost_ms ~ hippo_vol_mm3, data = memclinic), col = "blue")

That abline(lm(...)) line has already fitted a regression — the kind of model the Regression 1 lecture is about.

TipLabel your axes

xlab and ylab are not decoration. No plot should leave this room with memclinic$moca written along an axis.

Several plots at once

par(mfrow = c(rows, columns)) splits the plotting area into a grid.

par(mfrow = c(2, 2))
hist(memclinic$age,  main = "Age",  xlab = "years")
hist(memclinic$moca, main = "MoCA", xlab = "score")
boxplot(hippo_vol_mm3 ~ group, data = memclinic, ylab = "Hippocampal volume")
plot(memclinic$age, memclinic$hippo_vol_mm3,
     xlab = "Age", ylab = "Hippocampal volume")
par(mfrow = c(1, 1))     # always put it back

Practical 5 opens with par(mfrow = c(2, 2)); plot(m1) to get four diagnostic plots in one figure. This is why.

Wide and long

Our second file has one row per person and three reaction-time columns:

stroop <- read.csv("data/stroop-rm.csv")
head(stroop, 3)
nrow(stroop)
[1] 36

That is wide format. Most modelling functions want long format: one row per observation, with a column saying which condition it came from. You could build it by hand with what you already know:

long_manual <- rbind(
  data.frame(id = stroop$id, condition = "congruent",   rt = stroop$rt_congruent),
  data.frame(id = stroop$id, condition = "neutral",     rt = stroop$rt_neutral),
  data.frame(id = stroop$id, condition = "incongruent", rt = stroop$rt_incongruent)
)
nrow(long_manual)
[1] 108
head(long_manual, 3)

36 people × 3 conditions = 108 rows. reshape() does it in one call:

long <- reshape(stroop,
                direction = "long",
                varying   = c("rt_congruent", "rt_neutral", "rt_incongruent"),
                v.names   = "rt",
                timevar   = "condition",
                times     = c("congruent", "neutral", "incongruent"),
                idvar     = "id")
rownames(long) <- NULL
head(long, 3)
nrow(long)
[1] 108
Tip

reshape() is the least friendly function in base R. Nobody memorises its arguments — copy this call and change the names. (tidyr::pivot_longer() is the modern alternative; the appendix shows it.)

Joining the two files

stroop-rm.csv has no group column, on purpose. merge() attaches it from the cohort file, matching on id:

long <- merge(long, memclinic[, c("id", "group", "age")], by = "id")
head(long, 3)
tapply(long$rt, long$condition, mean)
  congruent incongruent     neutral 
   423.9167    542.8889    452.8889

Reaction time rises from congruent to neutral to incongruent — the Stroop effect.

The other way to draw this

Every regression script in this course uses ggplot2, so it is worth seeing the same picture in both dialects. The professor’s own comment in Regression1.R is “better graphic facilities with ggplot package”.

library(ggplot2)      # notice the masking message

ggplot(memclinic, aes(x = hippo_vol_mm3, y = stroop_cost_ms)) +
  geom_point(alpha = .6) +
  geom_smooth(method = "lm", se = FALSE) +
  labs(x = "Hippocampal volume (mm³)",
       y = "Stroop interference cost (ms)")

Three ideas and that is enough for now: aes() says which variable maps to which part of the picture, each geom_ adds a layer, and layers are joined with +. You do not need it here, but every regression script in the course uses it, so it is worth having seen once.

What to take away

  • In df[rows, columns], the comma is what separates the two. One column with a comma gives a vector, not a table.
  • ifelse() for two outcomes, dplyr::case_when() for more, first match wins.
  • A factor’s levels are alphabetical unless you set them. The first level is the baseline every model compares against.
  • tapply() and aggregate() summarise within groups.
  • Label your axes.
  • Wide is for reading, long is for modelling.
